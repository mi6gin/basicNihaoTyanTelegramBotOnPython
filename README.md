# Nihao Tyan Telegram Bot

Двуязычный Telegram-бот поддержки на Python 3.12 и aiogram 3. Пользователи создают обращения и следят за их статусом, администраторы отвечают через встроенную админ-панель.

## Возможности

- русский и английский интерфейс;
- регистрация пользователей и сохранение выбранного языка;
- создание и просмотр обращений с обязательной категорией;
- диалог из нескольких сообщений внутри обращения;
- фотографии и документы в новых и существующих обращениях;
- открытые и закрытые обращения;
- постоянные FSM-состояния в PostgreSQL;
- уведомления администраторов о новых обращениях;
- очередь обращений, ожидающих ответа администратора (включая повторные сообщения пользователя);
- просмотр всех обращений и открытых обращений по категориям со счётчиками, с возможностью показать закрытые;
- закрытие обращения пользователем или администратором;
- версионируемые миграции PostgreSQL через Alembic;
- защита inline-кнопок от использования другим пользователем;
- ежедневный журнал всех входящих сообщений, действий с обращениями и ошибок; сводка по дням в админ-меню.
- отправка полного отчёта о каждой ошибке администраторам текстовым файлом в Telegram;
- просмотр дневных записей и скачивание полного файла только администратором в личном чате;
- список известных пользователей и реестр групп/каналов, где бот появлялся, с отметкой о выходе.
- рассылка новостей и рекламных сообщений с URL-кнопкой из админ-панели после предварительного просмотра и подтверждения.

## Локальный запуск

Требуется Python 3.12 или новее.

```shell
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

```dotenv
BOT_TOKEN=токен_от_BotFather
DATABASE_URL=postgresql+asyncpg://bot:bot@localhost:5432/bot
ADMIN_IDS=123456789,987654321
LOG_LEVEL=INFO
DROP_PENDING_UPDATES=false
```

`ADMIN_IDS` — Telegram ID администраторов через запятую. При значении `DROP_PENDING_UPDATES=true` бот удалит накопившиеся во время простоя обновления при следующем запуске.

Создайте PostgreSQL-базу, примените схему и запустите бота:

```shell
alembic upgrade head
python -m scripts.import_sqlite
python main.py
```

Команда импорта один раз переносит существующие `data/users.db` и `data/appeals.db`, если они есть. Повторный запуск безопасен: завершённый импорт отмечается в PostgreSQL.

## Запуск в Docker

После создания `.env` выполните:

```shell
docker compose up --build -d
docker compose logs -f bot
```

PostgreSQL сохраняется в томе `postgres-data`, а журналы и старые SQLite-файлы для одноразового импорта — в `bot-data`. Контейнер ожидает готовность базы, применяет Alembic-миграции, импортирует старые данные и только затем запускает polling.

## Ежедневный журнал

Бот сохраняет все входящие сообщения, включая команды, сообщения администратора и неподдерживаемые вложения, в `data/logs/YYYY-MM-DD.jsonl`. Для текста и подписей сохраняется полный текст; для вложений — тип и метаданные, но не двоичный файл и не Telegram `file_id`. Время записи соответствует часовому поясу Алматы. В том же файле фиксируются создание, дополнение, ответ и закрытие обращения, а также ошибки. Известный токен бота в записях скрывается.

Сохраняются не более 30 дневных файлов. При появлении следующего дня самый старый журнал удаляется автоматически. В Docker журналы находятся в томе `bot-data` и не исчезают при пересборке образа. Каталог `data/logs` исключён из Git, поскольку сообщения могут содержать личные данные.

Ошибки уровня `ERROR` и выше записываются в дневной журнал с traceback, если он доступен, и отправляются каждому ID из `ADMIN_IDS` отдельным файлом `.txt`. При неудачной отправке ошибка выводится в логи контейнера без повторной отправки уведомления. Для получения файлов администратор должен сначала открыть личный чат с ботом.

Администратор может открыть «📊 Журнал по дням», выбрать дату, просмотреть записи по одной или скачать полный файл в личном чате. В записи входящего сообщения сохраняются ID, имя и username отправителя, а также ID, тип и название чата. Администратору также доступны списки известных пользователей и групп/каналов. Изменения участия бота в чате фиксируются отдельно; после выхода чат остаётся в реестре с неактивным статусом. Эти списки хранятся в PostgreSQL и не ограничены 30-дневным сроком файлов журнала.

В разделе «Рассылка» администратор выбирает обычное текстовое сообщение или рекламное сообщение с текстом, надписью кнопки и ссылкой `http://` или `https://`. Бот показывает предварительный просмотр и запрашивает подтверждение. Адресаты берутся из реестра пользователей порциями, отправка ограничена по скорости. После завершения администратор получает число доставленных, недоступных и неуспешных отправок. Пользователи, которые не открывали личный чат с ботом или заблокировали его, могут оказаться недоступны. При перезапуске бота текущая рассылка прервётся; уже доставленные сообщения не откатываются.

Telegram передаёт боту не все сообщения группы при включённом режиме приватности. Журнал фиксирует только те сообщения, которые Telegram действительно доставил боту. Группы, где бот состоял до введения реестра, появятся в списке после нового сообщения или события изменения участия. Меню поддержки и админские данные открываются только в личном чате.

## Проверка

Тесты не обращаются к Telegram. Для интеграционных тестов хранилища задайте отдельную PostgreSQL-базу (она будет очищена тестами):

```shell
TEST_DATABASE_URL=postgresql+asyncpg://bot:bot@localhost:5432/bot_test python -m unittest discover -v
```

## Пользовательский сценарий

1. Пользователь запускает `/start`, выбирает язык и категорию обращения, затем описывает проблему.
2. Обращение сохраняется, а администраторы получают уведомление с категорией и кнопкой просмотра.
3. Администратор отвечает пользователю прямо в Telegram.
4. Если пользователь дополняет обращение после ответа, оно возвращается в очередь «Ждут ответа». Диалог продолжается до закрытия.

Размер обращения и ответа ограничен 1500 символами, чтобы итоговые сообщения гарантированно помещались в лимит Telegram.

## Структура

- `main.py` — точка запуска;
- `manage.py` — настройка бота, команд и polling;
- `bot/commands/` — команды `/start` и `/help`;
- `bot/handlers/` — пользовательские и административные сценарии;
- `bot/keyboards/` — inline-клавиатуры;
- `storage/` — PostgreSQL-таблицы, запросы и FSM-хранилище;
- `migrations/` — Alembic-миграции схемы;
- `scripts/import_sqlite.py` — одноразовый перенос прежних SQLite-данных;
- `locales/` — русские и английские тексты;
- `tests/` — автоматические тесты;
- `Dockerfile` и `compose.yaml` — контейнерный запуск.
